# Модель задержки оплаты по УПД, версия delay-1.0

Модель по открытому УПД, срок оплаты которого не наступил, выдаёт вероятности задержки больше 7, 14, 30 и 90 дней (`p_7` … `p_90`, всегда не возрастают по k) и ожидаемое число дней задержки. Обучена на синтетике (десять партий), проверена на месяцах 25–29 окна данных, которые в обучении и подборе параметров не участвовали.

**Что значат метрики.** Реальных оплат УПД у нас нет. Метрики показывают, что модель восстанавливает заложенные в данные зависимости и не смотрит в будущее. О качестве на реальных оплатах они ничего не говорят: на оплатах банка модель переобучается.

## Что не выполнено

**1. Прирост к наивному правилу по p_14.** Модель 0,773, наивное правило 0,759: прирост +0,014 вместо 0,030. Для сравнения прирост по другим порогам: p_7 +0,008, p_30 +0,032, p_90 +0,096. Бустинг, которому дополнительно дали скрытые параметры генератора (класс дисциплины пары, PD без шума, признаки тренда), набирает на проверке только 0,778 (прирост +0,019): на этих данных история пары уже очень сильный предиктор, и простое правило её использует.

**2. MAE ожидаемых дней против медианы по паре.** Модель 9,99 дн., медиана по паре 8,24, прогноз «ноль дней» 9,21. Среднее проигрывает медиане по MAE при любом качестве: у точного условного среднего из генератора MAE 10,09. По RMSE модель лучше обоих простых прогнозов: модель 17,57, среднее по паре 17,79, медиана по паре 18,49 (точное среднее генератора 17,46).

**3. К-11 в партиях 03, 07 и 09** (УПД категорий 1–4 с p_90 выше 10%: 2, 0 и 1 против минимума 4). Максимум p_90 в партиях 0,10–0,14: модель уверена в риске больше 90 дней только для немногих УПД. Лечится в генераторе (пары с хроническими долгими задержками), данные не менялись.

## Как устроена модель

- Четыре бустинга LightGBM (по одному на `p_7`, `p_14`, `p_30`, `p_90`), признаков: 42, по разделу 8.3 ТЗ: УПД, сумма к обычной для пары, история пары, история покупателя у всех клиентов партии, покупатель, отрасль клиента. Тип стоп-фактора и сам стоп-фактор в признаках не используются.
- Параметры подобраны кросс-валидацией на обучающем периоде, пять частей, группы по УПД. Выбраны конфигурации: p_7: B, деревьев 499, p_14: C, деревьев 581, p_30: B, деревьев 215, p_90: B, деревьев 97.
- Калибровка Platt на предсказаниях вне обучающих частей (изотоническая на перекрёстной проверке не лучше). После калибровки вероятности упорядочиваются так, чтобы не возрастать по k.
- `expected_days`: регрессия (Tweedie) на закрытых УПД.
- `score_delay(upd_id, t, таблицы)` работает по одному УПД и пакетом, использует только данные не позже t. Один УПД считается за 0,05 с, пакет из 1219 УПД за 0,54 с (с загрузкой таблиц 0,12 с).

## Проверка на утечку

- Признаки 400 случайных строк пересчитаны по таблицам, урезанным до даты t: расхождений нет.
- AUC выше потолка ни по одному порогу.
- Обучение на перемешанных метках, p_14: среднее из пяти 0,511 (отдельные запуски от 0,478 до 0,537), при перемешанных метках проверки 0,501. Разброс отдельных запусков шире коридора 0,48–0,52, потому что строки одной пары похожи друг на друга.
